| Severity | Count |
|----------|-------|

| **High** | 4 |

The codebase is well-engineered with consistent use of bounds checking, `errdefer` chains,
checked arithmetic, and defensive patterns. No critical findings. The 4 High-severity findings
are in the WASM ABI layer (`capnp_free` lacking allocation tracking) and peer orchestration
(graceful shutdown never completing). The most impactful Medium findings are in codegen (group
reader missing typed list wrappers/defaults) and protocol (embargo ID collision).

## High Severity (4)

### R1 — Graceful Shutdown Never Completes (Track 4: Peer Orchestration)

- **File**: `src/rpc/level3/peer/return/peer_return_orchestration.zig:14`
- **Also**: `src/rpc/level3/peer.zig:1612-1616`
- **Trigger**: Call `peer.shutdown(callback)` while questions are outstanding, then let all Returns arrive normally.
- **Impact**: The shutdown callback never fires and the transport is never closed. `handleReturn` removes questions via `peer.questions.fetchRemove(answer_id)`, which bypasses the `removeQuestion()` method — the only place that checks `is_shutting_down && questions.count() == 0` and calls `completeShutdown()`. Result: hung shutdown with `is_shutting_down = true` and zero questions.
- **Fix direction**: After question removal in `handleReturn`, check the shutdown condition. Either call `removeQuestion` consistently, or add a post-return hook that checks `is_shutting_down && questions.count() == 0`.
- **Status**: open

### W1 — capnp_free: No Validation That Length Matches Original Allocation (Track 6: WASM)

- **File**: `src/wasm/capnp_host_abi.zig:306-314`
- **Trigger**: Host calls `capnp_free(ptr, wrong_len)` with a `len` that does not match the original allocation size.
- **Impact**: In Zig's allocator contract, calling `free` with a mismatched length is undefined behavior. Could corrupt allocator state or free wrong memory.
- **Fix direction**: Track allocated buffers in a `HashMap(usize, usize)` mapping pointer addresses to their allocated sizes. On free, validate that the provided length matches.
- **Status**: open

### W2 — capnp_free: Double-Free With No Protection (Track 6: WASM)

- **File**: `src/wasm/capnp_host_abi.zig:306-314`
- **Trigger**: Host calls `capnp_free(ptr, len)` twice with the same valid pointer.
- **Impact**: Double-free causes UB in the underlying allocator. Could corrupt WASM heap.
- **Fix direction**: Same tracking map as W1; remove on free; reject unknown pointers. The peer-specific `capnp_peer_free_host_call_frame` already demonstrates this pattern with `outstanding_host_call_frames`.
- **Status**: open

### W3 — capnp_free: Arbitrary Pointer Free From Host (Track 6: WASM)

- **File**: `src/wasm/capnp_host_abi.zig:306-314`
- **Trigger**: Host calls `capnp_free(arbitrary_ptr, len)` with a pointer never allocated by `capnp_alloc`.
- **Impact**: Calling `allocator.free` on untracked memory is UB.
- **Fix direction**: Same tracking map as W1/W2; reject frees of untracked pointers.
- **Status**: open

## Medium Severity (12)

### S5 — No Traversal Limit in Read Path Without validate() (Track 1: Serialization)

- **File**: `src/serialization/message.zig:972-984`
- **Trigger**: Parse a message using `Message.getRootStruct()` and follow pointers without calling `validate()` first. Deeply nested pointer graphs consume unbounded work.
- **Impact**: Amplification attack via crafted messages with valid but highly connected pointer structures.
- **Fix direction**: Document that `validate()` MUST be called before reading untrusted messages. Alternatively, add an optional traversal counter to `Message`.
- **Status**: open

### P1 / R2 — Embargo ID Collision on Wrapping (Tracks 2+4)

- **File**: `src/rpc/level3/peer/peer_control.zig:456-460`
- **Trigger**: Long-lived connection allocates >2^32 embargo IDs. Counter wraps via `+%=` and collides with existing entry.
- **Impact**: `put()` silently overwrites old embargo mapping. Orphaned promise ID never gets `embargoed` flag cleared, permanently blocking calls to that resolved import.
- **Fix direction**: Add probe-and-check loop matching `allocateQuestionId`. Probe `pending_embargoes.contains(next_embargo_id)` and return error if full.
- **Status**: open

### P2 — classifyCap Defaults to senderHosted for Unknown Cap IDs (Track 2)

- **File**: `src/rpc/level0/cap_table.zig:448-454`
- **Trigger**: A message builder has a capability pointer with a `cap_id` not in any table.
- **Impact**: Capability silently classified as `senderHosted`, causing remote peer to reference a nonexistent export ID. Protocol violation leading to `UnknownExport` errors.
- **Fix direction**: Return `error.UnknownCapabilityId` instead of defaulting.
- **Status**: open

### T1 — Transport.shutdown() Does Not Guard Against Use-After-Close of fd (Track 3)

- **File**: `src/rpc/level2/transport.zig:279-283`
- **Trigger**: Call `transport.deinit()` (closes fd, sets `fd_closed = true`), then call `shutdown()` from another thread with stale reference.
- **Impact**: `sysShutdown` called on potentially reused fd. Could shut down wrong socket.
- **Fix direction**: Add `if (self.fd_closed) return;` guard to `shutdown()`.
- **Status**: open

### T7 — Worker Pool deinit Does Not Join Worker Threads (Track 3)

- **File**: `src/rpc/integration/worker_pool.zig:122-127`
- **Trigger**: Call `deinit()` without waiting for `run()` to return, or from a different thread.
- **Impact**: Use-after-free of workers array while worker threads may still be running.
- **Fix direction**: Have `deinit()` join all worker threads before freeing. Document that `deinit()` must only be called after `run()` has returned.
- **Status**: open

### R3 — handleCall Duplicate Question ID Check Misses Forwarded Questions (Track 4)

- **File**: `src/rpc/level3/peer.zig:2021-2029`
- **Trigger**: Remote sends a Call whose `question_id` matches a forwarded question not yet in `resolved_answers`.
- **Impact**: Duplicate question ID accepted during the forwarding window, causing state corruption.
- **Fix direction**: Add `self.forwarded_questions.contains(call.question_id)` and `self.forwarded_tail_questions.contains(call.question_id)` to the duplicate check.
- **Status**: open

### R4 — bufferPendingReturn Overwrites on Duplicate Third-Party Answer ID (Track 4)

- **File**: `src/rpc/level3/peer/third_party/peer_third_party_returns.zig:32`
- **Trigger**: Two Return frames arrive for the same third-party answer ID before adoption.
- **Impact**: `put()` overwrites old value, leaking the previously buffered frame.
- **Fix direction**: Check `pending_returns.contains(answer_id)` before inserting. Free old frame or reject duplicate.
- **Status**: open

### G1 — Group Reader List Fields: Return Type vs Body Mismatch (Track 5: Codegen)

- **File**: `src/capnpc-zig/struct_gen.zig:638,753-755`
- **Trigger**: Cap'n Proto group containing a field of type `List(SomeEnum)`, `List(SomeStruct)`, `List(Data)`, or `List(SomeInterface)`.
- **Impact**: Compile error in generated code. Function signature declares typed wrapper (e.g., `EnumListReader(MyEnum)`) but body returns raw reader method result (`message.U16ListReader`).
- **Fix direction**: Port typed wrapper logic from `generateFieldGetter` (lines 404-517) into the group field getter at line 753.
- **Status**: open

### G2 — Group Reader Missing Default Value Handling for List Fields (Track 5: Codegen)

- **File**: `src/capnpc-zig/struct_gen.zig:753-756`
- **Trigger**: Cap'n Proto group containing a list field with a non-null default value.
- **Impact**: Generated code ignores list default values in group field getters.
- **Fix direction**: Port default value logic from `generateFieldGetter`'s list handling into `generateGroupFieldGetter`.
- **Status**: open

### G3 — Group Reader Missing Default Value Handling for Struct/AnyPointer Fields (Track 5: Codegen)

- **File**: `src/capnpc-zig/struct_gen.zig:743-751,757-758`
- **Trigger**: Cap'n Proto group containing a struct or any_pointer field with a non-null default.
- **Impact**: Generated code ignores struct and any_pointer default values in group field getters.
- **Fix direction**: Port default value logic from `generateFieldGetter` into the corresponding branches.
- **Status**: open

### W6 — No Global Cleanup Path for the peers HashMap (Track 6: WASM)

- **File**: `src/wasm/capnp_host_abi.zig:170`
- **Trigger**: WASM module torn down without calling `capnp_peer_free` for all peers.
- **Impact**: All `PeerState` objects and the `peers` HashMap are leaked. Benign on WASM (linear memory reclaimed), real leak on native.
- **Fix direction**: Add a `capnp_shutdown()` export that iterates peers, calls deinit+destroy on each, then deinits the map.
- **Status**: open

### E1 — markExportPromise Partial State on OOM (Track 7: Error Handling)

- **File**: `src/rpc/level0/cap_table.zig:91-95`
- **Trigger**: First `put` to `exports` succeeds, second `put` to `promised_exports` OOMs.
- **Impact**: Cap table inconsistent: ID in exports but not in promised_exports. Caller (`addPromiseExport`) has compensating errdefer, but `markExportPromise` itself doesn't clean up.
- **Fix direction**: Add `errdefer _ = self.exports.remove(export_id);` after the first `put`.
- **Status**: open

### E3 / S2 — encodeOffsetWords Uses debug.assert (Tracks 1+7)

- **File**: `src/serialization/message.zig:21`
- **Trigger**: Release build with offset exceeding 2^29 words (~4 GiB segment).
- **Impact**: Assert stripped in release; `@intCast` silently truncates, producing corrupt pointer.
- **Fix direction**: Replace `debug.assert` with proper error return.
- **Status**: open (extremely low practical risk)

### E4 — StreamState.handleReturn debug.assert for in_flight > 0 (Track 7)

- **File**: `src/rpc/level2/stream_state.zig:25`
- **Trigger**: `handleReturn` called more times than `noteCallSent` in release build.
- **Impact**: Silent u32 underflow in release-fast; trapping in release-safe. Counter never reaches zero again, drain callback never fires.
- **Fix direction**: Use `if (self.in_flight == 0) return error.NoInflightCalls;` or saturating subtraction.
- **Status**: open

### E6 — WASM ABI catch {} on Re-Insertion After fetchRemove (Track 7)

- **File**: `src/wasm/capnp_host_abi.zig:908`
- **Trigger**: `fetchRemove` succeeds, length mismatch detected, `put` to re-insert fails with OOM.
- **Impact**: Tracked host call frame permanently lost from tracking map.
- **Fix direction**: Validate length via `get` before `fetchRemove`. Only remove after validation passes.
- **Status**: open

## False Positives Reviewed (30+)

Key patterns confirmed safe across all tracks:

- **`swapRemove` + `break` in iteration**: Safe — no access after swap
- **`fetchRemove` returns entry**: Different from implicit free — entry returned for manual cleanup
- **Far pointer word offsets (`u29 * 8`)**: Cannot overflow even on 32-bit usize
- **Builder `u16 * 8` operations**: u16 sums can't overflow
- **`catch unreachable` on generated setters**: Writing primitives to pre-allocated data sections cannot fail
- **`+%=` on release counters**: Bounded by `max_table_size = 10,000`
- **Question ID wrapping**: Intentional recycling with collision probing
- **`ForwardCallContext` defer ordering**: Fields read by value before defer runs at scope exit
- **`StringHashMap` dual-index key lifetime**: Correctly ordered cleanup in both deinit and runtime paths
- **`PeerState = undefined` fields**: Idiomatic two-phase init; `deinit` only called on fully-initialized state
- **errdefer chains in `collectManifestSerdeEntries`**: Each errdefer covers all subsequent failures
- **XOR default encoding direction**: Symmetric — `(value XOR default) XOR default = value`
- **PascalCase type names**: All Zig keywords are lowercase; capitalized first letter prevents collision
